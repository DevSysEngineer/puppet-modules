# Agent Instructions

## Start Before Reading Project Content

Read this complete file and the root [README](README.md). All `.md` files directly in the repository root, and files named `AGENTS.md` at any depth, may be opened, read and searched without the secrets tool. For other project content, before it enters AI context, run `bundle exec project-tools-secrets PATH ...` locally and review only its metadata. For findings, use `bundle exec project-tools-secrets prepare` with explicit file selection and required context, then read only the released analysis tree. Withhold content on errors, incomplete coverage or uncertain masking; install unavailable tooling before reading. Do not inspect raw content to decide whether scanning is needed.

The full [local inspection and disclosure requirements](CONTRIBUTING.md#lokale-inspectie-vóór-inzage) remain authoritative, including the reading exception, Git-version inspection and incident reporting. Use the [scanner procedure](.tools/secrets/README.md#controleren-voor-het-lezen) and [prepared editing workflow](.tools/secrets/README.md#ontwikkelen-met-een-analysewerkboom); private mappings and recovery state belong to the write operation, not an AI session.

To read the scanner guide initially when its scan has findings, create a private JSON policy containing `{"files":[".tools/secrets/README.md"],"context":[]}`. From the repository root run `bundle exec project-tools-secrets prepare --root "$PWD" --policy POLICY --tree TREE --state STATE`, replacing the uppercase arguments with private physical paths outside the repository; source, tree and state must not contain each other, and tree and state must be new. Read `TREE/.tools/secrets/README.md` only when the result reports `complete: true` and `prepared: true`. Then follow that guide for further selection, context and closing the local operation.

## Required Reading Route

- Before editing, actually read and apply [CONTRIBUTING.md](CONTRIBUTING.md), [TESTS.md](TESTS.md), and the applicable norms selected below. A link alone is not evidence of loading.
- For any first-party code, read and apply the [general design rules](.tools/lint/puppet/docs/CODE_RULES.md#algemene-ontwerpregels). For Puppet, use the [lint workflow](.tools/lint/puppet/README.md#werkwijze-bij-een-wijziging) and [reading guide](.tools/lint/puppet/README.md#leeswijzer) to read the applicable language and resource rules.
- Read the relevant [documentation norms and information ownership](.tools/lint/puppet/docs/DOCUMENTATION_RULES.md#informatieplaatsing) for documentation or code comments, and [operational norms](.tools/lint/puppet/docs/OPERATIONAL_RULES.md) for managed files, permissions, security, services, shell, runtime dependencies or monitoring. These sources apply cumulatively; apply their manual criteria even when automated checks pass.
- Explicitly open local `AGENTS.md` files from repository root to every affected component before changing it, including when starting at root. Local instructions supplement the parent route; use the shared [authority and conflict rules](.tools/lint/puppet/docs/DOCUMENTATION_RULES.md#informatieplaatsing).
- For tooling maintenance, start with [`.tools/AGENTS.md`](.tools/AGENTS.md), then open the affected component instructions from its index and read its README contract. Apply this route by responsibility, including root Gemfile, Rakefile, `.github/` and consumer examples. Shared interfaces require the actual affected consumers' instructions and contracts.
- Expand the reading scope when further dependencies or integrations appear. Do not reread unchanged instructions already read in this task. Applying code norms under lint does not itself require lint development instructions; changing those norms does.

## Agent-Specific Instructions

- Check the active environment for instruction overrides and truncated text; read missing applicable material directly through the inspection route and report any unperformed verification. Keep essential routing at the start of instruction files. Do not automatically change personal agent settings. The [Codex discovery documentation](https://developers.openai.com/codex/guides/agents-md) describes startup discovery and the configurable combined-text limit; do not assume linked material has been loaded.
- Never create, amend or rewrite Git commits through Git commands, APIs or other tools. Leave validated changes in the working tree for human review and commit according to the [shared delivery workflow](CONTRIBUTING.md#afronden-en-wijzigingsreview).
- When asked to maintain instructions, use the shared [documentation maintenance criteria](.tools/lint/puppet/docs/DOCUMENTATION_RULES.md#afspraken-onderhouden). Keep general development knowledge at its shared owner and update this route only when needed to make agents read it.
